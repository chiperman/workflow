# 测试指南

本文档说明核心逻辑与 UI 组件的测试流程，确保系统稳定性与用户体验的一致性。

---

## 🤖 自动化测试

项目使用 **Jest** 与 **React Testing Library** 对核心逻辑进行单元测试。

### 1. 运行测试

```bash
# 运行所有测试
npm test

# 检查测试覆盖率
npm test -- --coverage
```

### 2. 测试结构 (就近原则)

项目采用 **Colocation Pattern**，`__tests__` 目录位于源代码同级（如 `src/services/__tests__`），便于维护与查找。

---

## 🧪 UI 组件测试清单

### ✅ TaskCard (任务卡片)

**核心测试点**:

- **执行逻辑**: 点击按钮应触发手动执行，并正确切换 `loading`, `success` 或 `error` 状态。
- **持久化显示**: 状态消息应保持显示直到被手动关闭或系统自动重置。
- **状态切换**: 定时任务开关应能有效切换 `enabled` 状态。

### ✅ Heatmap (签到热力图)

**核心测试点**:

- **网格渲染**: 每日方块应准确对应执行结果（绿色成功，红色失败）。
- **交互功能**: 年度选择器应能顺畅切换年份。
- **提示增强**: 悬浮显示的 Tooltip 应包含完整的日期（含年度）及详细的状态信息。

### ✅ Task Configuration Modal (任务配置弹窗)

**核心测试点**:

- **自动探测**: "Test & Detect Rules" 能够正确识别目标 URL 的成功模式并建议规则。
- **校验逻辑**: 支持智能匹配与复杂的 JSON 路径校验操作。
- **交互逻辑**: HTTP 与内部服务类型切换时，配置项应能即时联动。

---

## 🎨 视觉与响应式测试

### 响应式断点

- **移动端 (< 768px)**: 卡片采用单列布局，点击区域适配触控。
- **桌面端 (> 1024px)**: 完整的仪表盘视图，优化间距与层级。

### 交互动效

- **悬停反馈**: 所有可点击元素应具备即时的视觉反馈。
- **加载状态**: 使用 `framer-motion` 实现平滑的骨架屏动画切换。
- **错误降级**: 优雅的错误边界 UI，防止全局崩溃并提供恢复入口。
