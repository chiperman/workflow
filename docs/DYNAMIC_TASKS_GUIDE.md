# 动态任务系统架构

本项目采用数据驱动架构，将维护协议与执行逻辑解耦，实现任务的动态配置与自动巡检。

---

## 🏗️ 架构概览

系统基于四个核心层构建，确保高灵活性与统一的执行环境。

### 1. 数据库层 (`keep_alive`)

`keep_alive` 表是所有协议的单一事实来源。

- **元数据**: 存储服务 ID、显示名称、描述与分类。
- **协议配置**: 通过 JSON 记录 URL、HTTP 方法、Headers 以及请求体。
- **校验规则**: 定义成功判定标准，包括状态码及其响应内容路径匹配。

### 2. 服务层 (`DynamicService`)

通用执行引擎，运行时解析数据库配置并执行。

- **执行**: 向定义的目标节点发送异步请求。
- **验证**: 根据配置的 `rules` 自动解析并判断执行结果。
- **埋点**: 捕获执行耗时 (Duration) 与错误片段，辅助精准排查。

### 3. API 层 (`Protocol Standard`)

- **`/api/tasks/[id]`**: 统一触发入口，基于唯一 ID 定位执行逻辑。
- **`/api/cron-all`**: 动态扫描所有启用任务并并行执行。
- **`/api/service-config`**: 任务生命周期的 CRUD 全流程接口。

### 4. 表现层 (UI)

- **`TaskCard`**: 解耦的视图组件，渲染实时健康状态。
- **`TaskConfigModal`**: 集中配置界面，支持 **智能探测 (Smart Detection)** 以自动生成判定规则。

---

## 🔄 协议生命周期

1. **配置**: 通过仪表盘配置并持久化至数据库。
2. **发现**: 系统自动将新协议纳入健康检查与 Cron 周期。
3. **执行**: 手动或自动化触发统一任务端点。
4. **闭环**: `DynamicService` 应用规则并更新统计数据与热力图。
